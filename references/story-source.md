# 故事来源与剧情锁定规则

本文件用于 `/start`、`/story`、`/plan`。

## 一、五种创作来源

### 1. AI 原创 `ai_original`

用户只给题材、基调、体量或受众，由 AI 提出故事。

### 2. 用户脑洞 `user_idea`

用户可能只给一句话。例如：

> 一个穷书生同时遇上一狐一鬼，两名女子都说对方不是人，书生却以为她们只是在争风吃醋。

规则：

- 不得因为信息少就擅自换成别的故事。
- 先提炼核心命题、主角目标、冲突与因果，再补足人物与结局。
- 补全必须围绕原始脑洞，而不是绕开它。

### 3. 用户梗概 `user_synopsis`

用户已经给出较完整故事线。

规则：

- 先抽取事实，不先改写。
- 标记 `mustKeep`、`canChange`、`forbiddenChanges`。
- 修逻辑时优先使用“最小改动原则”。

### 4. 原著改编 `adaptation`

必须记录原著 / 民间故事名称、版本信息（如用户提供）、忠实度、保留项、允许改动项。

详细规则见 `adaptation-rules.md`。

### 5. 已有剧本重写 `rewrite`

先锁定用户要求：保留什么、修改什么、目标体量、目标风格。

禁止把“优化剧本”理解成“另写一篇”。

---

## 二、剧情锁定字段

```json
{
  "storyIdea": "",
  "mustKeep": [],
  "canChange": [],
  "forbiddenChanges": [],
  "endingPreference": ""
}
```

### `mustKeep`

最高优先级剧情约束，例如：

- 主角同时遇到狐女与鬼女
- 两名女子互相识破
- 主角误以为她们在争风吃醋
- 狐女实际上一直在救主角

这些内容在 `/plan`、`/outline`、`/script`、`/episode`、`/review` 中都必须逐项检查。

### `canChange`

允许为了影视化而调整，例如：

- 配角合并
- 场景压缩
- 事件顺序微调
- 对白现代化 / 古风化
- 反转出现时间

### `forbiddenChanges`

用户明确不接受的方向，例如：

- 不改成穿越
- 不加入系统
- 不把 HE 改成 BE
- 不更换主角

---

## 三、冲突处理优先级

发生规则冲突时：

1. 用户本轮明确要求
2. `mustKeep` / `forbiddenChanges`
3. 原著改编忠实度
4. 已确认的 `creative-plan.md`
5. 角色档案
6. 题材模板
7. 爽点 / 钩子 / 付费 / 反派模板

模板永远不能反过来覆盖用户锁定的故事。

---

## 四、最小改动原则

当发现故事存在逻辑问题时：

1. 先指出具体矛盾。
2. 优先补一个动机、伏笔、时间差、动作或对白即可解决的问题。
3. 只有小修无法成立时，才调整事件顺序。
4. 只有核心因果无法成立时，才建议重构。
5. 任何重构都不得自动越过 `mustKeep`。
